# OSS Hub

Платформа для авторов открытых репозиториев и контрибьюторов.

Живой продакшн: [oss-hub-nu.vercel.app](https://oss-hub-nu.vercel.app)

---

## Проблема

В классической open-source разработке на GitHub авторы и контрибьюторы регулярно сталкиваются с проблемами:
- Брошенные issues без ответов и ясного статуса;
- Отсутствие актуальных инструкций локального запуска;
- Дублирование работы: несколько разработчиков одновременно готовят один и тот же Pull Request;
- Публичный флуд в комментариях вместо конструктивного архитектурного диалога;
- Отсутствие прозрачных инструментов для формирования постоянной Core Team проекта.

## Возможности платформы

### 1. Maintainer CRM (`/projects/[slug]/crm`)
Выделенный полноэкранный воркспейс для автора репозитория:
- **Канбан-воронка заявок:** 4 этапа (Новые заявки, В разработке, PR на ревью, Завершено / В команде);
- **Live Drawer Chat:** встроенный тред общения мейнтейнера с кандидатом прямо внутри воркспейса;
- **Бэклог задач:** управление ручными задачами с указанием сложности (Easy, Medium, Hard), тегов и времени;
- **Вакансии и роли:** открытые позиции в команду с указанием требуемого коммитмента (часов в неделю);
- **Ростер участников:** база подтвержденных контрибьюторов и участников команды с контактами;
- **Режим во весь экран:** переключение воркспейса в режим без отвлекающих элементов.

### 2. Fast-Track Онбординг
- **1-Liner Quickstart:** готовая проверенная команда для клонирования и локального запуска;
- **Architecture Map:** карта ключевых файлов проекта (точка входа, роутинг, база данных);
- **Шаблон .env:** безопасный пример конфигурации окружения для быстрого старта.

### 3. Система бронирования задач (Claims)
- Контрибьютор отправляет заявку на задачу с кратким питчем своего решения;
- Мейнтейнер утверждает исполнителя, защищая задачу от дублирования;
- Привязка GitHub PR и автоматический переход в статус выполнения после мерджа.

### 4. Поиск команды (Team Finder)
- Публикация долгосрочных ролей в проект;
- Сбор заявок от разработчиков с опытом и контактами для связи.

## Технологический стек

- **Фреймворк:** Next.js 16 (App Router, Turbopack, React 19)
- **Язык:** TypeScript
- **Стилизация:** Tailwind CSS
- **База данных:** libSQL / Turso DB, Drizzle ORM
- **Аутентификация:** GitHub OAuth + криптографически подписанные HMAC-SHA256 сессии
- **API:** GitHub REST API v3
- **Безопасность:** Edge Rate Limiting, защита от сканеров, DOMPurify для Markdown

## Быстрый старт

### Требования
- Node.js 20+ или Bun 1.1+
- Аккаунт GitHub для OAuth-приложения

### Установка

1. Клонируйте репозиторий:
```bash
git clone https://github.com/lonestill/oss-hub.git
cd oss-hub
```

2. Установите зависимости:
```bash
bun install
# или
npm install
```

3. Настройте переменные окружения:
```bash
cp .env.example .env.local
```
Заполните параметры в `.env.local`:
- `TURSO_DATABASE_URL` (или оставьте пустым для локального SQLite `file:dev.db`)
- `GITHUB_CLIENT_ID` и `GITHUB_CLIENT_SECRET` (из настроек GitHub OAuth App)
- `SESSION_SECRET` (любая надежная случайная строка)

4. Запустите сервер разработки:
```bash
bun run dev
# или
npm run dev
```

Приложение будет доступно по адресу [http://localhost:3000](http://localhost:3000).
